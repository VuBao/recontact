# Email Provider Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Provide an exact Japanese template, MIME builder, replaceable provider interface, and Gmail/Google Workspace adapter suitable for Cloudflare Pages Functions.

**Architecture:** Provider-neutral orchestration calls `createMailProvider(env)`. The Gmail adapter refreshes OAuth tokens and calls Gmail REST with a MIMEText-generated base64url message. No Node-only `googleapis` SDK is introduced.

**Tech Stack:** JavaScript modules, Web `fetch`/Web Crypto APIs, `mimetext` from GitHub/npm, Node test runner.

**Spec:** `docs/superpowers/specs/2026-10-12-bulk-candidate-email-design.md`

## Global Constraints

- Branch: `codex/email-provider-core`; never commit to `main`.
- Reuse reviewed MIT-licensed GitHub code/library patterns; do not build a mail engine from scratch.
- Do not modify `index.html`, D1 schema, or API endpoints.
- Never print OAuth tokens, message bodies, or attachment bytes.

## Review Focus

- Exact Japanese copy and Unicode encoding.
- CR/LF/NUL header injection defenses.
- Gmail OAuth scope and normalized errors.
- Provider coupling exists only inside the Gmail adapter/factory.
